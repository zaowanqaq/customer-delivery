# AI 达人主页快速初筛

## 目标

在运营工作台新增一个独立的 AI 达人主页快速初筛页面。客户上传自己的达人库并输入自然语言需求后，系统仅访问每位达人主页可见的信息，给出前端结果表，不写入飞书多维表格。

首版用于初步筛选，不替代人工确认或后续的笔记详情分析。

## 输入

客户上传 CSV 或 XLSX 文件。模板固定为以下四列：

- 达人昵称
- 博主 ID
- 主页链接
- 达人价格

“博主 ID”与“主页链接”至少需要提供其中一项；昵称和价格原样展示。页面同时提供一段自然语言需求输入，例如“需要现在 IP 在浙江、主页之前有线下打卡内容的帅哥美女账号”。

## 筛选流程

1. 服务端用 DeepSeek 将自然语言需求转成结构化规则，包括地域、是否需要线下打卡经历、形象要求，以及可展示的需求标签。
2. 浏览器逐个打开达人主页，只采集页面当前可见的资料、IP 信息、简介和可见笔记卡片文字，并在有限滚动后截取一到两张主页截图。
3. 将结构化规则、可见文字和截图一起发送至 `google/gemma-4-31b-it:free`，要求其返回固定 JSON：判定、证据、理由和不确定项。
4. 服务端合并上传表中的昵称、ID、链接、价格与模型结果，持续向前端报告进度。

首版不调用小红书内部 API，不进入笔记详情页，不抓取完整历史笔记，也不将结果写入飞书。

## 结果展示

前端结果表固定为八列：

1. 序号
2. 是否符合筛选要求
3. 达人昵称
4. 博主 ID
5. 主页链接
6. IP 地
7. 达人类型
8. 达人价格

“是否符合筛选要求”只取三个值：`符合`、`不符合`、`待人工确认`。

“达人类型”不是预置分类，而是从本次需求拆解出的命中标签。例如“浙江本地｜线下打卡｜形象匹配”；信息不足时可显示“线下打卡｜形象待确认”。点击行可查看判断理由、可见证据和不确定项，但这些内容不增加表格列。

## 异常与人工确认

以下情况一律标记为“待人工确认”，不能误判为“不符合”：

- 主页要求登录、出现验证码、无法加载或链接失效。
- 页面可见信息不足以支持结论。
- 模型调用失败、限流或未能返回符合约定的 JSON。
- 模型明确标记低置信度，尤其是基于封面判断形象时。

“IP 地”只代表主页当前可见或最新公开展示的 IP 属地，不能解释为达人实时物理位置。“可去世界杯活动”在首版中仅按是否存在可见的线下打卡经历评估，不推断实际出行意愿或可用档期。

## 状态与数据保留

任务在服务端运行期间保存进度和结果，页面轮询显示已处理、待处理及异常数量。结果只在工作台展示，不同步到飞书；服务重启后未导出的任务结果不保证保留。

## 模型与密钥

- DeepSeek：只负责把用户需求解析成结构化筛选规则，并使用 JSON 输出模式。
- OpenRouter：使用用户选定的 `google/gemma-4-31b-it:free` 同时理解需求文本和主页截图，做证据判断。
- 所有密钥仅从环境变量 `DEEPSEEK_API_KEY` 与 `OPENROUTER_API_KEY` 读取，代码、日志、测试夹具与 Git 历史中均不保存密钥。

免费模型存在额度、限流与临时不可用风险，因此不会作为唯一的最终决策来源；调用异常会进入人工确认。OpenRouter 的免费模型限制以其官方限制页为准：<https://openrouter.ai/docs/api/reference/limits>。

## 验收标准

- 可以下载并上传四列表格模板，校验缺列和缺少 ID/链接的行。
- 可以输入需求并看到逐行处理进度。
- 可见主页信息足够时，八列结果完整展示，达人类型随需求动态变化。
- 无法访问、证据不足或模型异常的记录统一进入“待人工确认”。
- 不调用笔记详情抓取接口，不向飞书写入记录。
- Windows 与 macOS 均不依赖硬编码本地路径。
